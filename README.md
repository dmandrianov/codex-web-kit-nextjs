![Как Web Kit превращает обычное сообщение в следующий проверяемый шаг](docs/assets/readme/web-kit-flow.svg)

Web Kit — это набор промптов, правил и шаблонов для Codex. Он смотрит, что уже есть в проекте, объясняет текущее положение простыми словами и предлагает один следующий шаг.

Вам не нужно изучать библиотеку промптов или помнить правильный порядок работы. После установки пишите Codex обычным языком: «хочу сделать сайт», «проверь главную» или «добавь блок с тарифами».

> **Главная идея:** не просить Codex сделать весь сайт одним большим сообщением. Сначала разобраться в задаче, затем идти небольшими шагами и проверять результат по пути.

## Для кого

- Для создателей продуктов и предпринимателей, которые хотят собрать сайт вместе с Codex, но не хотят управлять десятками промптов вручную.
- Для дизайнеров и разработчиков, которым нужен повторяемый процесс: от смысла и структуры до кода и проверки.
- Для команд, которым важно не терять решения между задачами и продолжать работу с понятного места.

Web Kit не является готовой темой, библиотекой секций или «волшебным промптом». Он организует работу Codex вокруг вашего проекта и ваших материалов.

## Установка через Codex

Репозиторий открыт: приглашение или отдельный доступ не нужны.

### 1. Откройте свой проект

Откройте в Codex папку будущего или уже существующего сайта.

### 2. Отправьте ссылку и одно сообщение

Скопируйте этот текст в Codex:

```text
Установи Web Kit из последнего стабильного релиза этого репозитория
в текущий проект:
https://github.com/dmandrianov/codex-web-kit-nextjs

Проверь источник и файлы релиза перед установкой. Не создавай вложенный
Git-репозиторий и не меняй remote, ветки или историю моего проекта.
После установки посмотри, что уже есть в проекте, и предложи один
следующий шаг.
```

Codex сам проверит релиз, установит нужные файлы и сохранит собственные правила проекта. Если обнаружится конфликт, он остановится до изменений и объяснит, что нужно решить.

### 3. Продолжайте обычным сообщением

После установки специальная команда для запуска не нужна. Напишите задачу своими словами — Web Kit поможет Codex определить, с чего начать.

<details>
<summary><strong>GitHub CLI ещё не авторизован?</strong></summary>

Для проверки подписанных GitHub Releases и последующих обновлений Codex может попросить один раз войти через браузер:

```bash
gh auth login --hostname github.com --web
```

Не отправляйте в чат токен, пароль, приватный ключ или вывод `gh auth token`.

</details>

## Как с этим работать

Вы описываете результат, а Web Kit помогает Codex вести процесс:

1. **Понять исходную точку.** Codex смотрит материалы и уже готовые файлы.
2. **Выбрать один следующий шаг.** Например: уточнить бриф, спланировать страницу или собрать один блок.
3. **Показать результат для проверки.** Крупные решения не прячутся внутри длинной автоматической цепочки.
4. **Сохранить контекст.** После значимого шага Codex обновляет состояние проекта.
5. **Объяснить продолжение.** В конце вы получаете понятный следующий шаг, а не внутреннее название промпта.

<details>
<summary><strong>Какой путь умеет сопровождать Web Kit</strong></summary>

Идея и материалы → бриф → аудитория и предложение → структура страниц → визуальное направление → решение по поддержке контента и технической схеме → Next.js → сборка по блокам → проверка полных сценариев → техническая подготовка к публикации → передача результата.

Для интернет-магазинов есть отдельный слой: товары, каталог, карточка товара, корзина, оформление заказа, оплата и доставка сначала описываются как правила. До статуса готовности отдельно проверяется, какая система отвечает за цены и заказы, как подтверждается оплата и что происходит при повторном уведомлении или временной ошибке.

</details>

## Примеры первых сообщений

Не подбирайте «правильную формулу». Начните с того, что действительно хотите сделать:

```text
У меня есть идея сервиса и несколько заметок. Помоги понять, чего не хватает до хорошего брифа.
```

```text
Проект уже начат. Посмотри, что готово, и предложи один следующий шаг без переделки всего сайта.
```

```text
Хочу добавить на главную блок с тарифами. Сначала помоги разобраться со смыслом и текстом.
```

```text
Проверь, готов ли сайт к публикации и какие риски ещё остались.
```

Чтобы получить новую версию уже установленного Web Kit, достаточно написать:

```text
обнови базу
```

Перед обновлением Codex проверит источник, покажет конфликты и сделает резервную копию управляемых файлов. Git-настройки и история вашего проекта в этот процесс не входят.

## Что вы получаете

| Вместо | Web Kit помогает сделать |
| --- | --- |
| Одного огромного запроса «сделай сайт» | Последовательность небольших задач с понятным результатом |
| Ручного поиска нужного промпта | Выбор следующего шага по реальному состоянию проекта |
| Потерянных решений между задачами | Короткую память проекта в документах |
| Проверки только «код запускается» | Отдельные проверки текста, интерфейса, адаптива и работы в браузере |
| CMS и сложной инфраструктуры «на всякий случай» | Решение от реального способа работы людей после запуска |
| Готовых блоков без проверки общего результата | Полные сценарии заявки, публикации, аккаунта или покупки |
| Случайной публикации в конце | Подготовку домена, безопасности, поисковых настроек и проверки после запуска |

<details>
<summary><strong>Что именно устанавливается в проект</strong></summary>

- `AGENTS.md` — правила, по которым Codex определяет следующий шаг.
- `prompts/` — библиотека небольших рабочих этапов.
- `.prompt-kit/` — версия, проверка целостности и безопасное обновление.
- Шаблоны документов для брифа, страниц, блоков и интернет-магазина.

Файлы самого сайта, его Git-репозиторий и проектные документы остаются под контролем владельца проекта.

</details>

## Частые вопросы

<details>
<summary><strong>Нужно ли знать Next.js и уметь программировать?</strong></summary>

Для первого разговора — нет. Можно начать с идеи, материалов или уже существующего проекта. Но важные технические решения, безопасность, платежи и публикацию всё равно нужно проверять, а не принимать вслепую.

</details>

<details>
<summary><strong>Нужна ли мне CMS?</strong></summary>

Если вы продолжите сами менять сайт с помощью Codex или другого ИИ и готовы публиковать обычные изменения проекта, CMS чаще всего не нужна. Она добавит лишнюю платформу, настройки и ещё один способ менять тот же контент.

Если тексты, статьи, товары или страницы должны вести редакторы, контент-менеджеры или другие сотрудники без работы с кодом, Web Kit сначала уточнит их роли и процесс публикации, а затем поможет выбрать CMS. Решение принимается не «на будущее», а по реальному способу работы команды.

</details>

<details>
<summary><strong>Можно установить Web Kit в существующий проект?</strong></summary>

Да. Установщик сначала проверяет, какие управляемые файлы уже есть и не были ли они изменены. При конфликте Codex должен остановиться и показать его до записи.

</details>

<details>
<summary><strong>Codex будет каждый раз спрашивать, какой промпт использовать?</strong></summary>

Нет. Вы пишете обычную задачу. Codex определяет положение проекта, выбирает подходящий этап и показывает служебное имя промпта только после человеческого объяснения.

</details>

<details>
<summary><strong>Можно попросить сделать всю страницу сразу?</strong></summary>

Можно, но обычный маршрут идёт по смысловым блокам. Так проще увидеть ошибку в тексте, композиции или адаптиве до того, как она повторится на всей странице.

</details>

<details>
<summary><strong>Может ли кто-то изменить этот репозиторий без разрешения владельца?</strong></summary>

Нет. Публичный доступ позволяет читать, скачивать и делать собственную копию репозитория. Другие пользователи могут предложить правки через fork и Pull Request, но они не попадут в основной репозиторий, пока владелец или добавленный им участник с правом записи не примет их.

</details>
