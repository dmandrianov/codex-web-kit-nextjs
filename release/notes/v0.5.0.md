# Web Kit v0.5.0 — обновления без конфликта с Git проекта

В этой версии у Web Kit появился полноценный релизный контур. Теперь сам кит можно хранить и развивать в отдельном GitHub-репозитории, а проекты пользователей получают только проверенный набор файлов из GitHub Release.

## Что стало проще

- После первого перехода на `0.5.0` достаточно написать Codex: `обнови базу`.
- Codex сам проверит последнюю стабильную версию, скачает релиз, сверит контрольную сумму и покажет конфликты до изменения файлов.
- История изменений и правила миграции приезжают вместе с китом, но не занимают корень пользовательского проекта.

## Дизайн: сначала сильный вариант, потом полный аудит

В `0.5.0` также появился компактный цикл `creator -> render -> critic`. Перед первым визуальным вариантом Codex получает короткий положительный brief, утверждённые скриншоты, реальные материалы и только несколько правил, которые важны именно сейчас. После живого render он подключает полные UI/copy/anti-slop базы, называет не больше трёх главных проблем и делает один связный self-fix.

Это снижает риск стерильных «правильных» экранов, которые формально проходят длинный чеклист, но выглядят как отчёт или таблица. При этом факты, permissions, secrets, accessibility и смысл product states остаются жёсткими ограничениями.

Утверждение текста блока больше не притворяется утверждением ещё не собранного layout. Уже готовые дизайны не пересобираются автоматически — новый цикл применяется со следующей реальной визуальной задачей.

## Что защищено

- Собственный `.git` пользователя, его remote, ветки, hooks, commits и права доступа не меняются.
- `README.md`, документация, исходный код, package-файлы и локальные промпты проекта не входят в область обновления.
- В `AGENTS.md` заменяется только управляемый блок Prompt Kit; проектные правила снаружи сохраняются.
- Перед записью создаётся резервная копия, а неудачная транзакция откатывается.

## Как устроен релиз

Каждая версия получает два одинаковых по содержанию архива — ZIP и tar.gz — плюс `SHA256SUMS`. Внутри находится точный allowlist и `.prompt-kit/manifest.json` с хэшами официальных файлов. Автоматические проверки повторно собирают и проверяют пакет перед публикацией.

## Важно для существующих проектов

Переход с `0.4.22` и более ранних версий требует одного отдельного подтверждения: у старых установок ещё нет manifest, поэтому невозможно доказать, какие kit-файлы пользователь менял локально. После успешной установки `0.5.0` дальнейшие совместимые обновления становятся однофразовыми.

Стадия сайта, готовые документы и код при обновлении не откатываются. После проверки целостности Codex только сопоставит новые возможности workflow с текущим состоянием проекта и предложит необязательные улучшения.
