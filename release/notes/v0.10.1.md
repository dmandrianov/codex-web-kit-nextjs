# Web Kit v0.10.1

This patch corrects an overly broad secret-handling rule that prevented Codex from completing an explicitly requested local API-key setup.

## What changed

- A user-provided application API key or token may now be written, on explicit request, to a verified Git-ignored `.env`/`.env.local` file or an authorized secret store.
- The deployment env workflow verifies that the destination is untracked and ignored, preserves unrelated existing entries and avoids echoing the value.
- Project state, history, documentation and maintenance reports store only variable names and safe storage locations.
- A regression test prevents the blanket prohibition from returning.

## Safety boundary

- Secret values must not appear in responses, command arguments, patches, diffs, documentation, Git, logs, screenshots, reports or backups.
- `.env.example` remains value-free and contains only names or safe placeholders.
- Root passwords, SSH/private keys and passphrases are not accepted through this workflow.
- Updating the kit does not read, copy, rewrite or require resubmission of existing project secrets.

## Existing projects

This is a non-breaking Prompt Kit policy correction. Existing website stages, source code, local rules, environment files, secret stores and deployment configuration remain unchanged. The new behavior applies only when the user later provides an application secret and explicitly requests configuration.

## Distribution

The project remains public open source under the MIT License. The release package maps the canonical root `LICENSE` to `.prompt-kit/TERMS.md` only for updater `0.8.x` compatibility; the legacy filename does not add separate restrictions.
