# Web Kit v0.10.2

This patch turns safe local API-key setup into a clear, one-paste workflow for an ordinary user. Codex prepares the destination and updates the env file; the secret itself never has to pass through chat or a visible command.

## What changed

- The release now includes `.prompt-kit/secret-input.mjs`, a masked terminal helper for explicitly requested application API keys and tokens.
- Codex selects the exact server-side variable and verified Git-ignored env target, opens the hidden input and completes the write without echoing or returning the value.
- User-facing guidance names the real blocker and next action instead of saying only “system restriction” or telling the user to edit `.env` manually.
- Update guidance explains when a newly opened Codex task is required for changed `AGENTS.md` rules to take effect.

## Safety boundary

- Secret values are not accepted through chat, command arguments, patches, visible stdin, documentation, Git or helper output.
- The helper rejects tracked or non-ignored targets, symlinks, public/client variables, password/private-key material, multiline values and duplicate assignments.
- Writes use a restrictive ignored temporary file and preserve unrelated env entries. Existing env files are not touched merely because the kit is updated.
- A technical permission-profile denial is explained, not bypassed; the supported alternatives are an authorized local terminal or the selected secret store.

## Existing projects

This is a non-breaking Prompt Kit workflow improvement. Existing source code, website stage, local rules, env files, values and deployment configuration remain unchanged during update. If a Codex task was already open while the kit changed, open a new task before testing the new managed rule.

## Distribution

The project remains public open source under the MIT License. The release package maps the canonical root `LICENSE` to `.prompt-kit/TERMS.md` only for updater `0.8.x` compatibility; the legacy filename does not add separate restrictions.
