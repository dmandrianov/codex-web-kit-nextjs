# Web Kit v0.6.0 — правильный адаптив и закрытые обновления

Эта версия закрывает скрытую проблему responsive-дизайна: сайт мог выглядеть правильно на финальном скриншоте, но сначала показывать layout для другого размера, а затем перестраиваться после загрузки JavaScript.

Она продолжает Sol-friendly цикл из `0.5.0`: короткий creator context, live render, critic до трёх findings и один self-fix. Новый responsive contract добавляет доказательство первого кадра, но не возвращает длинный checklist перед созданием дизайна.

Эта же версия переводит доставку Web Kit на закрытую подписочную схему. Releases находятся в private GitHub Organization repository, подписчик получает outside-collaborator role `Read`, один раз входит в GitHub CLI через браузер и дальше обновляет базу фразой `обнови базу`.

## Что изменилось

- Основную mobile/desktop/wide геометрию теперь выбирает CSS до первого видимого кадра.
- Серверная разметка и первый клиентский render сохраняют одну структуру; hydration не должна исправлять canvas.
- `window.innerWidth`, `matchMedia` и mount effects остаются допустимыми для проверки или поведения, но не для выбора initial layout.
- Изображения и измеряемые surfaces заранее резервируют место, поэтому не сдвигают страницу после загрузки.
- Responsive media подбирается под фактическую ширину элемента: мобильный или 1440 canvas не должен без причины загружать 4K-файл.

## Как это проверяется

Browser QA выставляет viewport до свежей загрузки, сравнивает первый и установившийся кадр, проверяет hydration, фактически выбранный media resource и источник любого сдвига. Обычный settled screenshot больше не считается достаточным доказательством.

## Как работает закрытое обновление

- Payment email используется для учёта оплаты, а подтверждённый GitHub username определяет фактический repository access.
- Updater доверяет embedded numeric repository ID, проверяет private Organization source и скачивает assets через browser-authenticated `gh` без запроса или вывода token.
- Публикуются только immutable releases: все assets сначала прикрепляются к draft, а после публикации updater проверяет `immutable: true`, подписанную release attestation и происхождение локальных TAR.GZ/`SHA256SUMS` до распаковки.
- Rename/transfer того же repository поддерживается при неизменном numeric ID; новый ID требует отдельной trusted migration.
- `.prompt-kit/TERMS.md` разрешает использовать и изменять скачанные версии в собственных и клиентских проектах, но запрещает standalone redistribution, resale, передачу точного private repository/release URL, credentials и archives третьим лицам.
- После отмены подписки repository и future updates становятся недоступны, а версии, скачанные во время активной подписки, продолжают работать и могут использоваться по TERMS.
- Git, remotes, branches и history пользовательского проекта не меняются.

## Для существующих проектов

Автоматический redesign не нужен. После обновления можно точечно дополнить `layout-rules.md`, проверить shared styling foundation и провести fresh-load test на одной representative route. Текущая стадия проекта и утверждённый визуальный курс сохраняются.
