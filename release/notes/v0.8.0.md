# Web Kit v0.8.0 — сильнее статьи и тексты страниц

Эта версия добавляет отдельный маршрут для новых SEO-статей и усиливает обычные тексты сайта без нового длинного этапа.

## Новые SEO-статьи

Для статьи, blog post, guide, comparison, listicle, review, pillar article или FAQ-материала Prompt Kit теперь явно вызывает оригинальный внешний `$seo-content-writer`.

Skill не копируется в Prompt Kit и не переписывается. Перед работой проверяются его preserved tag `v9.9.12`, pinned commit, `SKILL.md` и четыре обязательных reference-файла. Если identity не совпала, статья не генерируется через молчаливый fallback.

Факты проекта, разрешённые claims, источники и `[needs source]` остаются под контролем Prompt Kit. Внешний skill отвечает за структуру статьи, естественное размещение запроса, snippet/FAQ/link recommendations и собственную CORE-EEAT проверку.

## Обычные тексты страниц

Hero, CTA, карточки, формы и обычный block content preview не запускают полный article workflow. Вместо этого они получают короткий нативный контракт:

- прямой ответ до убеждения;
- совпадение обещания заголовка с body;
- опора для каждого material claim;
- конкретные сущности и действия вместо общих слов;
- CTA, соответствующий готовности человека;
- смысловое завершение блока.

`Site copy fast pass` выполняется внутри существующего content preview или smoke-check. Новый этап, отдельное согласование и research на каждый блок не добавляются. Полный редакторский check остаётся длинному, критичному или рискованному тексту.

## Что изменится в существующих проектах

Стадия сайта, утверждённый текст, дизайн и production-код остаются действительными. Новый слой начинает работать со следующей задачей на текст. Уже утверждённые страницы не переписываются автоматически.

Полный `seo-content-writer` нужен только для новых статей или по явной просьбе пользователя. Это внешняя pinned dependency: она устанавливается отдельно и не входит в release archive Prompt Kit.

## Проверенный эффект

Контрольное сравнение на реальном Tension-блоке сайта reference-project сохранило удачный заголовок, но сделало lead и пары конкретнее. Новый fast pass нашёл слабости, которые прежний большой checklist отметил как пройденные: абстрактный первый ответ, несопоставленные claims и общие слова вместо предметов проекта.
