## Назначение

Этот проект использует Prompt Kit для разработки сайтов на Next.js через Codex. Codex сам определяет тип запроса, загружает только нужные правила и выполняет один проверяемый шаг за раз.

Базовый стек, если проект не задаёт другое: Next.js App Router, TypeScript, `src/`, компонентный подход и настроенные проверки проекта.

## Локальные правила проекта

- Правила конкретного сайта находятся после managed-блока или в `docs/project-rules.md`.
- Прочитай применимые локальные правила до работы. Более узкое локальное правило имеет приоритет, если не нарушает truth, permissions, safety, secrets или accessibility.
- Не помещай историю другого проекта в Prompt Kit. `docs/project-state.md` и optional `docs/project-history.md` принадлежат только текущему сайту.

## Четыре маршрута запроса

Сначала выбери один маршрут:

1. `status` — пользователь спрашивает, что готово, что мешает или что дальше. Прочитай только текущий снимок в `docs/project-state.md`; историю открывай лишь для восстановления старого решения.
2. `direct` — небольшая диагностика или локальная правка без перехода стадии. Осмотри затронутые файлы и релевантный короткий стандарт; не загружай Router, INDEX и большие справочники без причины.
3. `staged` — запрос двигает создание сайта между этапами. Прочитай текущий снимок, затем `prompts/ROUTER.md`, выбери один основной промпт и открой его полностью.
4. `cross-cutting` — обновление Prompt Kit, CMS/архитектура, e-commerce, SEO-статья, technical SEO или deployment. Сразу используй профильный маршрут ниже; основная стадия сайта меняется только если профильный промпт этого требует.

`prompts/INDEX.md` — справочный каталог. Открывай его только при неоднозначном выборе внутри уже определённой стадии.

## Алгоритм работы

1. Определи маршрут по просьбе пользователя и фактическому состоянию файлов.
2. Проверь локальные правила, границы задачи и разрешённые действия.
3. Для `status` или `direct` работай по минимальному контексту и сохрани текущую стадию.
4. Для `staged` или `cross-cutting` выбери один основной промпт и максимум один действительно необходимый вспомогательный.
5. Открой выбранный промпт полностью и следуй его разделам `Когда использовать`, `Контекст`, `Ограничения`, `Процесс`, `Output`, `Done when`, `Follow-up`.
6. Не загружай заранее будущие стадии и полные reference-базы. Для creator используй только применимые правила; полный compliance оставляй critic/quality.
7. Выполни проверки пропорционально риску. Не запускай тяжёлую цепочку для простой локальной правки.
8. После значимого шага обнови короткий текущий снимок `docs/project-state.md`, не превращая его в журнал всей работы.
9. Заверши понятным результатом и одним следующим действием. Крупный следующий этап начинай только после подтверждения.

## Cross-cutting маршруты

- Prompt Kit update: по просьбе `обнови базу / кит / Prompt Kit` используй транзакцию `prompts/_maintenance/01-update-prompt-kit.md` → integrity → alignment. До preflight не заменяй файлы и не меняй Git проекта.
- Prompt Kit source release: используй `prompts/_maintenance/05-release-prompt-kit.md`. Build/verify не разрешает commit, tag, push или GitHub Release без отдельного явного разрешения.
- CMS и Next.js architecture: сначала выясни, кто меняет контент. Если владелец продолжает работать через Codex/ИИ и обычный deploy подходит, CMS по умолчанию не нужна. Для редакторов без кода сначала зафиксируй workflow и используй `prompts/06-nextjs-setup/02-technical-architecture.md`.
- E-commerce: перед каталогом, PDP, корзиной или checkout закрой недостающие prompts из `prompts/11-ecommerce/`, включая operations/payment safety и review.
- Technical SEO/deployment: metadata, canonical, robots, sitemap, schema, statuses и redirects используют technical SEO baseline; сервер, SSH, env, домен, SSL и production deploy используют `prompts/12-deployment/` и оба SEO gate.
- SEO article: новая статья, guide, comparison, listicle, review, pillar или FAQ под поисковый запрос использует `prompts/_content/01-write-seo-article.md` и явный `$seo-content-writer`; текущая стадия сайта сохраняется.
- Обычный page copy: hero, CTA, карточки, формы и content preview используют `Site copy fast pass`; полный article skill для них не нужен.
- gpt-taste: только explicit `page`, `block` или `component` route для выразительной marketing/editorial задачи. Dashboard, checkout, forms, quality, SEO, deployment и maintenance не вызывают его автоматически.

## Всегда действующие ограничения

- Не придумывай факты, цены, отзывы, гарантии, юридические условия, наличие, сроки или бизнес-правила. Неподтверждённое помечай `needs confirmation`.
- Не запрашивай, не печатай и не сохраняй passwords, tokens, private keys, root-пароли или secret env values.
- Не выполняй destructive или внешние state-changing действия без ясного разрешения и точной проверки цели.
- Не добавляй зависимости, CMS, database, auth или сервис «на будущее» без подтверждённой необходимости.
- Не меняй соседнюю business logic, если задача локальная.
- Не объединяй стратегию, дизайн, реализацию, quality и deployment в один скрытый проход.
- Не выдавай lint/build или один открывшийся экран за проверку полного сценария форм, auth, CMS, commerce или интеграций.
- Не копируй чужой сайт или screenshot 1:1.
- Не утверждай visible UI без применимых browser/responsive/accessibility проверок из выбранного промпта.
- Не редактируй kit-owned промпты внутри пользовательского сайта вместо локального override: такие изменения создают update conflict.

## Короткий контракт ответа

Пользователь сначала должен понять:

1. что произошло или что сейчас известно;
2. зачем это важно;
3. требуется ли от него действие.

Пути, команды, внутренние стадии и названия промптов показывай после человеческого смысла. Если ничего не требуется, напиши это прямо. Полный `prompts/_knowledge/codex-user-response-quality.md` открывай для сложного отчёта, блокера или неоднозначной передачи результата, а не перед каждым сообщением.

После значимого шага добавь:

```md
Следующий шаг: [одно действие обычными словами]
Зачем: [короткая причина]
```

Если продолжать нельзя или работа завершена, скажи это вместо искусственного следующего этапа.
