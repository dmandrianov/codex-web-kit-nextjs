# Добавить проектные правила в AGENTS.md

## Когда использовать

После финального `project-brief.md`, до настройки проекта, дизайна и верстки.

## Роль Codex

Ты действуешь как senior frontend engineer и технический редактор, который превращает рабочие договоренности в короткие инструкции для Codex.

## Цель

Сохранить router-слой Prompt Kit в `AGENTS.md` и добавить проектные правила конкретного сайта в раздел `## Project-specific context`, чтобы Codex понимал стек, структуру, команды, ограничения и критерии качества.

Если в проект уже скопирован Prompt Kit, не удаляй router-инструкции из `AGENTS.md`. Router-слой должен быть внутри managed-блока `PROMPT_KIT`, а проектные правила должны быть вне managed-блока. Добавь или обнови раздел `## Project-specific context`. Если проектных правил много, вынеси детали в `docs/project-rules.md` и оставь ссылку в `AGENTS.md`.

## Контекст, который нужно дать

- `project-brief.md`.
- `docs/project-state.md`, если он уже есть.
- Тип сайта и краткое описание проекта из брифа.
- Предпочитаемый стек, если он отличается от дефолта Next.js App Router + TypeScript + `src/`.
- Команды запуска, lint, typecheck, build и тестов, если уже известны.
- Особые правила дизайна, контента или безопасности.
- Предпочтения по документации и комментариям в коде, если они отличаются от дефолта.
- Существующие файлы проекта, если проект уже создан.

## Ограничения

- Не превращай `AGENTS.md` в длинную документацию.
- Не удаляй router-инструкции Prompt Kit из `AGENTS.md`.
- Не переписывай `AGENTS.md` с нуля, если там уже есть router-слой Prompt Kit.
- Не помещай `Project-specific context` внутрь managed-блока `PROMPT_KIT`.
- Не удаляй markers `<!-- PROMPT_KIT:BEGIN managed version=... -->` и `<!-- PROMPT_KIT:END -->`.
- Если `project-brief.md` отсутствует, не продолжай этот промпт: вернись к `prompts/00-intake-brief/07-finalize-project-brief.md`.
- Не добавляй правила, которые нельзя проверить.
- Не добавляй правило "комментировать всё": комментарии нужны только для неочевидной логики и важных ограничений.
- Не меняй код проекта в этом промпте, кроме `AGENTS.md`, `docs/project-rules.md` и `docs/project-state.md`, если пользователь не попросил отдельно.
- Для Next.js по умолчанию используй App Router, TypeScript, `src/` и компонентный подход.

## Процесс

1. Проверь наличие `project-brief.md`. Если его нет, остановись и предложи вернуться к intake.
2. Изучи текущую структуру проекта и существующий `AGENTS.md`.
3. Проверь, что router-секции Prompt Kit сохранены: назначение, алгоритм, модель стадий, маршрутизация, ограничения.
4. Проверь наличие managed-блока:
   - если markers есть, не меняй содержимое managed-блока без причины;
   - если markers нет, используй `prompts/_maintenance/03-migrate-agents-md.md` или добавь markers вокруг router-слоя перед проектными правилами.
5. Добавь или обнови `## Project-specific context` вне managed-блока.
6. Внутри `Project-specific context` используй разделы: назначение проекта, тип сайта, стек, структура, команды, правила разработки, правила документации, правила комментариев в коде, правила дизайна/контента, критерии готовности, открытые вопросы.
7. Если правил много, вынеси подробности в `docs/project-rules.md`, а в `AGENTS.md` оставь короткую ссылку.
8. В `Правила документации` обязательно добавь: после каждого значимого изменения проверять, нужно ли обновить docs; при изменении команд, структуры, поведения, пользовательских сценариев, дизайн-решений, API, env или ограничений обновлять соответствующий документ; если docs не обновлены, явно объяснять почему.
9. В `Правила комментариев в коде` обязательно добавь: комментировать только неочевидную логику, workaround, интеграции, важные ограничения и временные решения; не добавлять очевидные комментарии, которые пересказывают код.
10. Создай или обнови `docs/project-state.md`: stage `rules-ready`, отмечены `Project brief approved` и `AGENTS.md created`, указан следующий рекомендуемый промпт.
11. Проверь, что файл не дублирует подробную документацию и не содержит непроверяемых правил.

## Output

Обновленный `AGENTS.md` с сохранённым router-слоем, при необходимости `docs/project-rules.md`, обновленный `docs/project-state.md` и краткое резюме добавленных проектных правил.

## Done when

- `AGENTS.md` создан или обновлен без удаления Prompt Kit router.
- Router-слой находится внутри `PROMPT_KIT` managed-блока.
- В `AGENTS.md` есть `## Project-specific context`.
- `Project-specific context` находится вне managed-блока.
- В проектных правилах есть назначение проекта, стек, команды и критерии качества.
- В проектных правилах есть дисциплина документации: docs поддерживаются актуальными после значимых изменений.
- В проектных правилах есть дисциплина комментариев: комментарии добавляются только там, где они объясняют неочевидное.
- Если правил много, детали вынесены в `docs/project-rules.md`.
- `docs/project-state.md` создан или обновлен.
- Файл короткий и пригоден для автоматической загрузки Codex.
- Открытые вопросы явно отмечены.
